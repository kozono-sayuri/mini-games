# Étoile Arcade — Sayuri's Mini Games

一座以原創角色與幻想世界觀包裝的輕量小遊戲館，也是記錄人類與 AI 協作開發流程的作品集專案。

- 線上網站：https://kozono-sayuri.github.io/mini-games/
- GitHub：https://github.com/kozono-sayuri/mini-games
- 個人首頁：https://kozono-sayuri.github.io/

## 專案定位

遊戲本身多為踩地雷、接龍、貪吃蛇等經典玩法，因此本專案不以「發明新遊戲」為主要賣點，而是透過以下方式建立特殊性：

- 每款遊戲都有一位原創女主角或男主角。
- 每位角色都有姓名、身分、台詞、篇章名稱與專屬場景。
- 遊戲首頁是一座會運行的角色星系，而不是一般卡片選單。
- 每款遊戲頁面的背景、色彩、介面與故事必須對應該角色的世界。
- 使用者不需登入，開啟即可遊玩，適合工作空檔短暫休息。
- 所有遊戲目前皆為單機玩法；棋類遊戲以玩家對 AI 為主。

## 統一世界觀與視覺規劃

遊戲館名稱為 **Étoile Arcade**。六位主人公來自不同幻想國度，但共享同一個華麗、神祕且成熟的原創動漫宇宙。

### 遊戲館入口

- 首頁核心意象：以 Étoile 為中心的幻想太陽系。
- 多層軌道必須有不同大小、速度與運行方向。
- 每顆角色星體應能對應一款遊戲；已完成的遊戲可以點擊進入。
- 動態效果必須支援 `prefers-reduced-motion`，避免造成暈眩。
- 主色為星夜深紫、酒紅、玫瑰粉與古金色。

## 遊戲頁面一致性規範

新增或修改任何遊戲時，必須同時檢查：

1. 遊戲卡封面角色與遊戲頁角色一致。
2. 頁面背景與角色的國度、服裝及配色一致。
3. 中央遊戲區具有足夠對比，背景不能妨礙操作和閱讀。
4. 電腦版不可留下缺乏設計的大面積空白區域。
5. 手機版不依賴滑鼠右鍵，必須提供觸控操作方式。
6. 動畫需尊重「減少動態效果」設定。
7. 遊戲可重新開始，並清楚呈現狀態與操作說明。
8. 不加入線上多人對戰、帳號或後端，除非日後另行決策。
9. AI 對手應優先確保反應速度與娛樂性，不追求競技級棋力。
10. 圖像必須為原創內容，不直接模仿既有作品、角色或特定畫師。

## 新增遊戲流程

1. 先定義角色、篇章、場景、色彩與一句角色台詞。
2. 在 `src/` 建立遊戲邏輯與畫面模組。
3. 將遊戲資料加入 `src/games.js`。
4. 在 `src/app.js` 註冊遊戲路由。
5. 建立與角色一致的遊戲頁背景資產。
6. 測試滑鼠、鍵盤、觸控與響應式版面。
7. 確認無障礙文字與減少動態效果支援。
8. 更新本 README 的功能清單、角色表與注意事項。
9. 執行檢查後提交，透過 GitHub Pages 發布。

## README 維護規則

每次新增遊戲、角色、場景、功能、依賴、發布方式或重要 UI 決策時，都必須同步更新本 README。

至少確認以下內容是否需要修改：

- 專案定位
- 統一世界觀與視覺規劃
- 角色與遊戲對照
- 遊戲頁面一致性規範
- 目前內容
- 新增遊戲流程
- 重要注意事項
- 更新紀錄

README 是作品集的一部分，不只是安裝說明。它應能讓面試官理解需求、設計決策、技術限制、AI 協作方式與專案演進。

## 重要注意事項

- 網站使用 GitHub Pages 發布，所有網址與素材引用必須支援 `/mini-games/` 子路徑。
- 遊戲路由目前使用 Hash Router，避免 GitHub Pages 重新整理子頁面時發生 404。
- 圖像資產可能較大；新增圖片時需注意首頁載入速度與手機流量。
- 不可將生成圖片留在暫存位置；網站使用的最終資產必須存入 `assets/`。
- 不得提交 API 金鑰、登入資訊或其他機密資料。
- 新功能不能破壞現有遊戲、GitHub Pages 工作流程或個人首頁的雙向連結。
- 發布前至少執行 JavaScript 語法檢查、`git diff --check`，並確認公開網址能正常回應。

## AI 協作原則

AI 協助需求拆解、方案比較、程式實作、素材生成、測試與文件整理；專案擁有者負責：

- 定義產品方向與驗收標準。
- 選擇或拒絕 AI 提案。
- 審查程式、圖像與文案。
- 實際試玩並回報體驗問題。
- 承擔最終品質與發布決策。
